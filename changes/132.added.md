An agent can now say that it acts for its caller, and the runtime holds it to that.

`Principal` is who a run acts for and what they hold; `Agent.scopes` is what the agent
declares it needs. `AgentIdentity.resolve` intersects the two once at run start and freezes
the result, so what a run may reach is one value rather than a history of settings. Nothing
in the module widens a scope set — `narrowed_to` is the only combinator — and `ScopeSet`
compares names in one normal form, because `Bookings:Read` from one product and
`bookings:read` from another is otherwise an intersection that silently empties.

`Agent.tool_scopes` says which scopes each tool needs. A tool whose scopes the caller does
not hold is not declared to the model and is refused at dispatch with `AuthorisationError`
naming the missing scope, the agent and the subject — so an operator widens the grant they
own instead of reading a downstream 403 that names nothing, and the request is never made.

Absence fails closed. An agent that declares scopes and finds no principal bound refuses at
construction rather than falling back to the process identity, which is the escalation this
prevents. A caller whose authority has already lapsed is refused the same way, and one that
lapses mid-run is refused at the next dispatch. An agent that declares no scopes is
unchanged.

Delegation only narrows: `narrowed` intersects a peer's declaration with what is effective
here and records the chain, so an agent holding more than its caller cannot be invoked as a
way around the refusal. A system-initiated run is modelled as a principal like any other,
and a durable continuation runs on a recorded delegation whose expiry is required rather
than inherited. `AgentIdentity.unused` names declared scopes nothing reached for, so a
defensive declaration can be trimmed with evidence.
