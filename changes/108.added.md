surface: tesserix_adk.workflows.durable
---

An agent run can now be a resumable unit of work. `AgentWorkflow` drives the same loop as the
in-process runtime while performing no I/O itself: model calls and tool calls are the only
execution points, each a typed serialisable input and a validated result, recorded in a
`Journal` under a step id derived from the run's position. A worker that dies and restarts
replays the loop, finds the completed steps, and executes none of them again — the resumed
run's answer, iteration count and usage ledger match a run that was never interrupted.

Everything the workflow decides is arithmetic — iteration, usage, pending approval, autonomy
grant, terminal state — which is what makes a replay reach the same decisions. Nothing here
imports a workflow engine: the kit supplies the driver and the payloads, and binding them to
Temporal activities belongs to the deployment and the optional `tesserix-adk[workflows]`
extra.

The transcript never travels. A model activity receives a handle to the run's history, and an
input without one is refused rather than sent with nothing to resolve. An input or result over
`PAYLOAD_LIMIT_BYTES` raises the new `PayloadTooLargeError` naming the step and the size,
because a retrieval result truncated to fit is still a plausible-looking answer. An
`ActivityContext` without a tenant raises `MissingTenantContextError`: a worker serves every
tenant, so its own identity is not a default, and user, scopes and trace id ride along on
every input.

An unavailable provider is retried, then reported with the attempt count and step while the
partial state stays inspectable. Cancellation is raced against the activity in flight rather
than awaited, so a completion nobody is listening to stops consuming. Token streaming is not
available on this path and says so through `STREAMING_UNSUPPORTED` rather than degrading
quietly.
