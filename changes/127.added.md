Content the caller did not write is now data everywhere it goes, rather than a paragraph of
prompt wording asking a model not to obey it. `TrustLevel` and `Origin` decide it: retrieval,
tool results, MCP results and peer-agent output are `untrusted`, and nothing a document says
about itself moves it up a level, because nothing reads the claim. A peer agent is no more
trusted than a web page — an A2A response is content from a party this run does not control,
and speaking fluent runtime is the attack, not a credential.

`ContentSource` carries the origin *and* the name — a URL, a tool name, an MCP server, a peer
agent's id — because "untrusted" alone is not actionable and a reviewer needs the thing to go
and look at. `Message.trust` is stamped from the role at construction, so nothing forgets it,
and may be set lower but never higher: a tool result relabelled as a system turn is the
injection, written in Python.

`sealed` wraps untrusted text in an envelope whose delimiter is a digest of the content it
holds. A fixed fence is one the attacker has already read in the docs; this one closes early
only by writing a delimiter derived from a document containing that delimiter. The seal is
deterministic, because a prompt prefix cached on its bytes must not change between two runs
that assembled the same thing, and the source is escaped into the attribute rather than
restricted, since a retrieval source is a URL.

`InjectionGuard` names what it recognises rather than calling it suspicious: `override`,
`impersonation`, `tool_shaped`, `fence`, `encoded`, `system_echo`, `metadata`, `split` and
`unscanned`. It normalises first, so a payload spelled in Cyrillic look-alikes is read the way
the model will read it, and the override pattern covers the languages a corpus is most often
mixed in. The caller's own turn is not screened for disobedience — a user telling the agent to
disregard what it was told is the caller exercising the run. Blocking is the default;
`block=False` annotates and continues, which is what a consumer picks when their corpus is
full of runbooks and support macros, because a guard that blocks a whole corpus on one match
is a guard that gets turned off.

`InjectionSuspectedError` names the source and the match codes, and records the matched span
as a length rather than as text: an error that quotes the payload puts it into every log that
catches it.

`Containment` is the defence screening only gathers evidence for. Untrusted content does not
widen the tool allowlist, change the principal or the tenant, or introduce a system directive
— those three are what an injection is trying to reach, and the prose is only how it asks.
Narrowing is always allowed, since content taking capability away is not an escalation, and
trusted origins pass through, because containment is about where a change came from.

`weakest` carries trust across a hand-off: an agent that retrieves a poisoned page, summarises
it and passes the summary on has laundered it unless the trust travels too. Screening is
bounded at `SCAN_LIMIT` characters and reports the tail it did not read as a signal the guard
blocks on, so an oversized payload fails closed rather than passing unread. The detector now
lives in `core` and is shared by the retrieval boundary and the guardrail chain, because two
copies drift and the copy that drifts is the one nobody is testing against a fresh corpus.
