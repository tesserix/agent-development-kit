Tenant scoping in a store adapter is now derived rather than passed. `Partition.current()`
reads the bound tenant context and builds the key prefix, the purge pattern and the bound
`WHERE` clause from it, so a forgotten prefix or a dropped predicate is not something a
call site can express. Outside a scope it raises `MissingTenantContextError`: absence is
never read as every tenant.

A read is checked as well as filtered. `Partition.verify` and `Partition.only` refuse a
record whose stored tenant is not the bound one — including an unlabelled record, which
predates the guarantee rather than belonging to us — and raise the new
`TenantIsolationError` without returning any of the page. Filtering it away quietly would
leave a botched backfill in place for the next read to leak. `Isolator` wraps the shape
an adapter needs: it resolves the partition before the store is called, so an unscoped
read never reaches the database, and checks everything that comes back.

Bulk work is either refused or split. `partitioned()` turns a mixed batch into one batch
per tenant; a write batch that spans the bound tenant raises rather than running as one
statement whose scope is the union of everybody in it.

`ADAPTER_GUARANTEES` states, per store adapter, which mechanism enforces the separation
and — the part that matters — what it does not protect against. `IsolationGuarantee`
cannot be constructed with an empty `limits`. `PartitionMechanism` deliberately offers no
post-filtered option: dropping foreign rows from the top `k` returns fewer than `k` of our
own whenever a neighbour ranks higher, which reads as a thin answer rather than a bug.

`ErasureSweep` records what each verification query counted after a tenant-scoped delete,
across rows, embeddings, summaries and cache keys; a sweep that counted nothing is refused,
because verifying nothing is not evidence that nothing remains.
