The tools a run may call are now resolved once, from every layer that has a say, into a
value that cannot be widened while the run is in flight.

`ToolAllowlist.resolve` intersects the agent's declaration, the tenant's entitlement and
the caller's scopes. The narrowest source wins. A source that states nothing passes `None`
and narrows nothing, which is not the same as a source stating an empty set — an empty
allowlist is valid and refuses everything.

Enforcement is in the dispatch path, after argument validation and before execution:
`AgentRunner` now resolves the allowlist per dispatch from the agent and the tenant policy
in force, so a tool the tenant's plan excludes is refused even where the agent declares it,
and is not declared to the model in the first place. It applies identically to native, MCP
and peer-agent tools.

`ToolNotPermittedError` carries which layer refused, so an operator fixes the setting they
own rather than the one below it. Refusals are not negotiable and are not free:
`ToolAllowlistGuard` counts every attempt including the refused ones, so a looping model
spends the run's caps rather than retrying forever.

Names are compared under one normal form — `canonical` applies NFKC, strips and case-folds
— so a capitalised and a full-width spelling are one permission rather than three. Two
declared names that collapse to the same form are refused at resolution. Delegation to a
peer agent can only narrow, so a peer with a broader declaration cannot proxy around the
layer that refused.

See [`docs/tool-allowlists.md`](../docs/tool-allowlists.md).
