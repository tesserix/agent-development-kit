Retry and timeout numbers are now declared per activity class rather than picked once for
the worker. A reasoning call that streams for nine minutes is healthy and a default
heartbeat timeout reads it as hung; a tool that charges a card is not healthy to repeat and
a default retry policy repeats it three times. `ActivityClass` and
`DEFAULT_ACTIVITY_POLICIES` give `MODEL`, `TOOL`, `RETRIEVAL` and `MEMORY` their own
windows, and the defaults are values a patch release may retune — `ActivityPolicy` is the
surface.

`NEVER_RETRYABLE` keeps two questions apart: whether a failure is a fault at all, and how
long to wait before trying again. A guardrail block, a schema violation, a budget breach, an
approval denial and a scope escalation are answers, and no consumer raising `max_attempts`
turns one into a fault. Anything outside the kit's hierarchy is left alone, because the kit
does not know what repeating it repeats.

`attempts_for_tool` reads what the tool declared instead of guessing: an effectful tool gets
one attempt, a tool that declared nothing is treated as effectful, and an idempotency key
gives the attempts back because the second call then lands on the first call's result.
`activity_policy_for` derives the heartbeat window from the timeout the tool declared —
never under 5s, never over 60s, always inside the activity — and an `ActivityPolicy` whose
heartbeat window is wider than the activity is refused at construction, since nothing could
ever breach it.

`Heartbeater` beats three times per window, so one lost beat is not read as a death, and
never once per token, which is a write per token. A `Heartbeat` carries a step, a token
count, a chunk count and a time, and `is_result` is permanently `False`: a heartbeat
carrying the partial text is read as an answer by the first consumer in a hurry.

`ActivityAttempts` draws its jitter inside the activity, never on the workflow path, and
the ADK-W002 replay guard now names `random.uniform` and `random.gauss` for that reason. A
wait that would outlast `start_to_close_seconds` is cut to what is left and reported as
`truncated` rather than dropped silently. Each attempt is charged against the run's ceiling
*before* it is made, so a retry the allowance cannot cover never happens and the ceiling is
never widened; the resulting `BudgetExceededError` reports the attempts spent under
`details["attempts"]`. `AttemptBudget` caps a fan-out's retries in one shared pool, because
ten branches retrying three times each is thirty calls at a provider that is already
struggling.
