Credential and scope propagation to MCP servers.

A configured MCP server is one connection shared by every tenant in the process. So the
authority travels with the call and never with the connection: `McpAuthorizer.authorise`
mints a credential per call for one tenant, one audience and one narrowed set of scopes,
whether the transport underneath is a fresh HTTP request or a stdio session that has been
open for hours.

`McpServerAuth` declares an allowlist rather than a request. What a server receives is the
run's effective scopes intersected with what the call needs and with what that server was
configured for, so a server reaches nothing nobody configured it for however wide the run
is. `narrowed_for` answers the same question without minting anything, for negotiation: a
server asking for elevated scopes during initialisation moves the grant down or leaves it
alone, and a server-initiated capability change narrows to the empty set, refused here
rather than at the far side as an opaque `403`.

`AuthorisedCall` separates the two renderings on purpose. `headers()` carries the
credential; `meta()` and `span_attributes()` carry only the shape of the authority —
tenant, subject, run, agent, granted scopes — because both are copied into logs, traces
and in some servers the tool result itself.

`ServerSessions` leases pooled sessions keyed by server, tenant and caller, and a lease
refuses to serve anyone else. A per-call scoped credential does not help if the connection
it travelled over is already authenticated as somebody else.

`McpAuthError` carries an `McpAuthReason` — unauthenticated, insufficient scope, expired —
because only one of the three is fixed by re-minting, and `from_status` classifies a
server's response. It stays distinct from `AuthorisationError`, which is the kit refusing
before the call. When minting fails, nothing half-authorised is returned for a session to
reuse or retry against.

The kit ships no MCP transport, and this package declares the structural protocols it
needs (`CredentialSource`, `CallCredential`) rather than importing them: `mcp` and `tools`
are siblings in the layering. `tesserix_adk.tools.CredentialBroker` satisfies both. See
[`docs/mcp-credentials.md`](../docs/mcp-credentials.md).
